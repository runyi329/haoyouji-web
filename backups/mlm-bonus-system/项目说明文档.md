## 六、与脉动网的 SSO 对接架构

### 整体流程

```
用户在脉动网登录
    ↓
点击积分商城"奖金制度"入口
    ↓
脉动网前端跳转到 /mlm-bonus 页面（内部路径）
    ↓
MlmBonusPage.tsx 调用后端 trpc.auth.mlmSsoLink
    ↓
脉动网后端用 HMAC-SHA256 生成签名链接
    签名内容：uid:name:ts
    密钥：HAOYOUJI_SHARED_SECRET
    有效期：5分钟（防重放攻击）
    ↓
iframe src 设为签名链接（https://bonus.jiangyuchen.cn/api/auth/external-login?uid=...&sign=...）
    ↓
奖金平台验证签名，自动登录用户
    ↓
用户无感知进入奖金平台
```

### 相关代码位置

**脉动网（haoyouji-web）：**
- 生成签名链接：`server/routers.ts` → `auth.mlmSsoLink` 过程（约第 2783 行）
- iframe 页面：`client/src/pages/MlmBonusPage.tsx`
- 积分商城入口：`client/src/pages/Home.tsx`（约第 1253 行）
- 路由注册：`client/src/App.tsx` → `/mlm-bonus` 路由

**奖金平台（mlm-bonus-system）：**
- 验证签名端点：`server/_core/oauth.ts` → `/api/auth/external-login`（约第 20-60 行）
- 允许 iframe 嵌入的响应头：`server/_core/index.ts`（`Content-Security-Policy: frame-ancestors`）

### 安全说明

- HMAC 密钥只存在于两个系统的**服务端**，前端不可见
- 时间戳有效期 5 分钟，防止链接被重放
- 奖金平台响应头设置 `frame-ancestors 'self' https://jiangyuchen.cn https://www.jiangyuchen.cn`，只允许脉动网域名嵌入

## 十二、合并到脉动网主站操作指南

> 本章节记录将奖金平台合并到脉动网主站的完整步骤。合并前请先阅读规则 005 → H-8 小节。

### 合并前检查清单

| 检查项 | 操作 |
|---|---|
| 技术栈版本一致 | 对照规则 005 H-1.5，确认 react/tRPC/drizzle/tailwind 版本与脉动网一致 |
| 路由命名无冲突 | 在脉动网 `server/routers.ts` 搜索 `mlmBonus`，确认无同名过程 |
| 表名无冲突 | 在脉动网 `drizzle/schema.ts` 搜索 `mlm_`，确认无重名表 |
| 数据已备份 | 从 Manus 后台 Database 面板导出全量数据，本地保存 |
| 脉动网代码已拉最新 | `cd haoyouji-web && git pull --rebase` |

### 第一阶段：前端合并

1. **复制页面文件**
   ```bash
   cp -r client/src/pages/ 脉动网/client/src/pages/mlm-bonus/
   # 若有同名文件，先重命名加前缀（如 MlmHome.tsx）
   ```

2. **复制专属组件**
   ```bash
   cp -r client/src/components/ 脉动网/client/src/components/
   # 跳过已存在的通用组件（Button、Card 等）
   ```

3. **修改 tRPC 调用路径**：将页面里的 `trpc.xxx.useQuery()` 改为 `trpc.mlmBonus.xxx.useQuery()`

4. **删除 SSO 相关代码**：删除 `Login.tsx`、外部登录跳转逻辑，改用 `useAuth()` 获取当前用户

5. **注册路由**：在脉动网 `client/src/App.tsx` 添加：
   ```tsx
   <Route path="/mlm-bonus" component={MlmHome} />
   <Route path="/mlm-bonus/:id" component={MlmDetail} />
   ```

6. **在脉动网导航中添加入口**：替换原来的 iframe 入口，指向 `/mlm-bonus` 路由

---

### 第二阶段：后端合并

1. **复制路由文件**
   ```bash
   cp server/mlm-bonus-router.ts 脉动网/server/
   cp server/mlm-bonus-engine.ts 脉动网/server/
   cp server/mlm-syjk-engine.ts 脉动网/server/
   ```

2. **修改 import 路径**：将路由文件顶部的 `../_core/trpc` 等路径调整为脉动网的相对路径

3. **删除 SSO 验证端点**：删除或注释 `server/_core/oauth.ts` 里的 `/api/auth/external-login` 端点及 HMAC 验证逻辑

4. **替换用户来源**：路由文件里通过 JWT 解析用户 ID 的地方，改为直接读 `ctx.user.id`

5. **在主路由注册**：在脉动网 `server/routers.ts` 顶部添加：
   ```typescript
   import { mlmBonusRouter } from "./mlm-bonus-router";
   // 在 appRouter 的 router({...}) 里加：
   mlmBonus: mlmBonusRouter,
   ```

6. **删除脉动网中的 SSO 生成端点**：删除 `server/routers.ts` 里的 `auth.mlmSsoLink` 过程（约第 2790 行）

---

### 第三阶段：数据库迁移

1. **导出子项目数据**：在 Manus 后台 Database 面板导出以下表的全量数据：
   - `mlm_companies`（公司列表）
   - `mlm_schemes`（奖金方案）
   - `mlm_simulations`（模拟记录）
   - `user`（用户表，仅导出业务字段，不导出密码等敏感字段）

2. **合并 Schema 定义**：将 `drizzle/schema.ts` 里的表定义追加到脉动网 `drizzle/schema.ts` 末尾

3. **生成并执行迁移 SQL**：
   ```bash
   pnpm drizzle-kit generate  # 生成迁移 SQL
   # 读取生成的 .sql 文件，在脉动网 Database 面板执行
   ```

4. **导入历史数据**：通过脉动网 Database 面板导入导出的数据
   - ✅ 用户 ID 字段无需转换：子项目通过 SSO 传入的用户 ID 与脉动网 users 表 ID 一致

5. **验证数据完整性**：执行关键查询，确认记录数与子项目原数据库一致
