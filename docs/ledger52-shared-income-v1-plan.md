# 52号账本 T+0「共享收益」方案（V2：共享优先）

> **核心决定**：任意关联用户的现货或合约订单，在平仓后形成**正向净收益**时，管理员可先从该笔平仓的正向净收益中手动分配共享收益；剩余收益再按本次平仓已固化的原分佣快照比例结算。

**适用范围**：52号账本 T+0 速记账本，金额单位为 U，日期以北京时间自然日计。当前尚未发生任何实际共享收益发放，因此本规则自第一笔发放开始统一适用。

## 1. 结算口径

设某笔平仓订单扣除开仓及平仓手续费后的净收益为 `P`，本次管理员手动分配的共享收益合计为 `S`：

```text
仅当 P > 0 时可发放共享收益
0 ≤ S ≤ floor(P × 100) / 100
普通分佣结算基数 R = max(0, P - S)
```

之后以该笔平仓已固化的收益分配快照结算 `R`。若一笔平仓由多个 FIFO 开仓切片组成，沿用既有 FIFO 与快照归属计算，并将普通分佣结果按 `R / P` 统一缩放，保证：

```text
Σ 普通分佣 + Σ 共享收益 = P
```

共享收益不再以“管理员在原分佣快照中必须占有份额”为前提；订单最初登记给谁、原快照是否含管理员，都不影响本单正向净收益能否用于共享。

### 示例

某笔平仓订单净收益为 `100.00 U`，原快照为 A 70%、B 30%，管理员发放共享收益 `20.00 U`：

| 项目 | 金额 |
| --- | ---: |
| 本单共享收益 | 20.00 U |
| 剩余普通分佣基数 | 80.00 U |
| A 按原快照结算 | 56.00 U |
| B 按原快照结算 | 24.00 U |
| 合计 | 100.00 U |

## 2. 平仓确认与权限

管理员在填写平仓价格、数量并进入第二次确认后，系统用同一套 FIFO、手续费和净收益公式预览：

- 本单全部净收益；
- 本单可共享金额（正向净收益的整笔金额，按 U 分向下取整）；
- 候选用户的未平仓情况、已实现收益、共享收益参考与年化参考；
- 本次分配总额与剩余金额。

管理员可以跳过共享直接确认平仓，也可以选择一人或多人并手动输入金额。共享收款人暂维持现有限制：不能是来源订单关联用户，也不能是当前操作管理员。

后端在真正提交时重新计算并校验，不信任前端预览：

- 只有正向净收益订单可携带共享分配；
- 合计不得超过本单可共享金额；
- 收款用户必须存在；
- 平仓、平仓分佣快照、共享收益转账写入同一数据库事务；
- 任一步失败，整笔平仓回滚，前端保留确认页并显示服务端错误。

## 3. 数据模型与兼容

表 `ledger52_t0_journal_shared_income_transfers` 继续保存：

- `closing_entry_id`：来源平仓订单；
- `source_user_id`：来源订单关联用户；
- `recipient_user_id`、`amount`：共享收益收款人及金额；
- `source_net_pnl`：提交时复核的本单净收益；
- `manager_pool_amount`：为兼容既有列名而保留，V2 语义为“本单可共享正向净收益上限”；
- `reduces_regular_distribution=1`：标明该共享收益已经占用本单普通分佣结算基数。

读取端按 `closing_entry_id` 汇总所有 `reduces_regular_distribution=1` 的金额，以同一个值驱动成员订单投影、收益账本、历史盈利筛选、候选 XIRR 和全局资金账本。这样共享收益不会与普通分佣重复计入。

## 4. 用户端展示边界

普通用户端包括两种身份，均保持既有卡片和流水风格：

1. **原订单下单人**：继续看到原订单和原有样式。系统在后台以共享后的剩余收益计算其普通分佣；页面不写“扣除后”“调剂”“管理员”或内部结算原因。
2. **共享收益收款人**：继续仅看到“共享收益”标签、金额和可核对的来源订单信息；不显示来源用户身份、原分佣比例、谁被影响、管理员操作或内部平衡信息。

共享收益不进入收款人的仓位、均价、FIFO、可平数量或挂单计算，只作为其一笔已入账收益参与收益账本与年化参考。

## 5. 管理端平衡参考

管理端可以继续查看每位用户累计收到的共享收益，以及其来源订单累计支持的共享收益，作为人工判断参考。该参考不构成债务、待回补、自动扣减、冻结或强制对齐逻辑。

## 6. 验收矩阵

1. 原订单快照中没有管理员份额，但本单正向净收益、共享为 `0`：平仓正常保存。
2. 同一条件下共享金额大于 `0` 且不超过本单净收益：平仓与共享转账原子写入成功。
3. 共享金额超过本单正向净收益：服务端拒绝，平仓与共享记录均不落库。
4. 本单 `P=100`、共享 `S=20`、原快照 70%/30%：普通分佣为 56/24，共享收款人为 20，合计严格为 100。
5. 负收益、打平或未关联用户订单：不展示共享分配区，但可正常确认平仓。
6. 原订单下单人与共享收款人的客户端均不出现“扣除”“调剂”“管理员”或内部比例话术。
